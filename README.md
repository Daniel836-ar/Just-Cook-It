# Just Cook It 🍳

**Just Cook It** - веб-приложение на Spring Boot, которое подбирает рецепты по тем ингредиентам, что уже есть у пользователя на кухне. Пользователь регистрируется, добавляет в список имеющиеся продукты и указывает их количество - приложение находит подходящие рецепты из базы и показывает инструкцию по приготовлению.

## 🚀 Запуск проекта локально

Docker Compose поднимает сразу два контейнера - приложение (`app`, порт `8080`) и базу данных (`db`, `postgres:16`).

**Шаги:**

1. Клонируйте репозиторий и перейдите в папку проекта:

   ```bash
   git clone git@github.com:Daniel836-ar/Just-Cook-It.git
   cd Just-Cook-It
   ```

2. Создайте файл `.env` в корне проекта (на основе `.env.example`) и при необходимости укажите свои учётные данные БД:

   ```bash
   cp .env.example .env
   ```

   ```dotenv
   DB_USER=postgres
   DB_PASSWORD=postgres
   ```

   > Если `.env` не создавать - сработают значения по умолчанию (`postgres` / `postgres`).

3. Соберите и запустите контейнеры:

   ```bash
   docker compose up --build
   ```

   При первом запуске Gradle соберёт `build/libs/app.jar`, после чего поднимется приложение и база. Дождитесь сообщения `Started RecipeApplication`.

4. Откройте в браузере **[http://localhost:8080/](http://localhost:8080/)** - приложение автоматически перенаправит вас на страницу входа.

**Остановить приложение:**

```bash
docker compose down
```

Полностью удалить данные БД (том `postgres_data`) вместе с контейнерами:

```bash
docker compose down -v
```

### 🔧 Переопределение `.env`

Всё, что касается подключения к БД, читается из переменных окружения, поэтому настройки можно переопределить двумя способами:

| Способ | Как |
|--------|-----|
| **Через `.env` (для Docker Compose)** | Измените значения `DB_USER` и `DB_PASSWORD` в `.env` - Docker Compose автоматически подхватит их при запуске. |
| **Через переменные окружения (для локального запуска и `bootRun`)** | Задайте `DB_HOST`, `DB_PORT`, `DB_NAME`, `DB_USER`, `DB_PASSWORD` в окружении - они переопределят дефолты из `application.properties`. |

Дефолтные значения в `application.properties`:

```properties
spring.datasource.url=jdbc:postgresql://${DB_HOST:localhost}:${DB_PORT:5432}/${DB_NAME:mydb}
spring.datasource.username=${DB_USER:postgres}
spring.datasource.password=${DB_PASSWORD:local_pass}
```

> `application.properties` можно править напрямую, но по возможности используйте переменные окружения - так настройки не попадут в коммит.

## 🍽 Как пользоваться приложением

### 1. Регистрация

Перейдите на **[http://localhost:8080/registration](http://localhost:8080/registration)** и заполните форму:

- **Имя** - как к вам обращаться;
- **Email** - логин для входа;
- **Пароль** - минимум 6 символов.

Нажмите **«Зарегистрироваться»**. При успехе вас перенаправит на страницу входа с сообщением *«Регистрация прошла успешно. Теперь можно войти.»*.

> Если email уже занят или пароль короче 6 символов - появится сообщение об ошибке, а введённые данные сохранятся в форме.

### 2. Вход

Перейдите на **[http://localhost:8080/login](http://localhost:8080/login)** (или перейдите по кнопке «Уже есть аккаунт? Войти» со страницы регистрации):

- введите **email** и **пароль**;
- нажмите **«Войти»**.

При успешном входе вы попадёте на главную страницу **[http://localhost:8080/](http://localhost:8080/)**. В правом верхнем углу будет отображаться email пользователя и кнопка **«Выйти»**.

> Если данные неверны, появится сообщение *«Неверный email или пароль.»*.

### 3. Добавление ингредиентов

На главной странице в поле **«Введите ингредиент, который у вас есть !»** введите название продукта (например, `Помидор`) и нажмите **«Добавить в список»**.

- Ингредиент появится в блоке **«Ваш список»** вместе с единицей измерения (гр, шт и т.д.).
- В строке ингредиента укажите **количество** - это важно, чтобы алгоритм корректно сравнил ваши запасы с рецептом.
- Повторите шаг для каждого продукта.

> ⚠️ Ингредиент ищется по точному имени, и добавляются только те продукты, которые уже есть в базе (см. [Демо-данные](#-демо-данные)). Регистр не важен - `помидор`, `Помидор` и `ПОМИДОР` обрабатываются одинаково.

### 4. Поиск рецептов

Когда список готов, нажмите **«Найти рецепты по этим данным»**. Откроется страница результатов **[http://localhost:8080/result](http://localhost:8080/result)**, где для каждого подходящего рецепта выводятся:

- **название рецепта**;
- **инструкция по приготовлению**.

Если ничего не подошло - отобразится сообщение *«К сожалению, по вашему запросу рецептов не найдено.»*.

### 5. Возврат на главную / выход

- **«← Вернуться на главную»** - возвращает на `http://localhost:8080/`.
- Кнопка **«Выйти»** в правом верхнем углу - завершает сессию и перенаправляет на `/login?logout`.

## 🥕 Демо-данные

При первом запуске (только если таблица `recipes` пуста) `CommandLineRunner` (`org.example.recipe.service.Main`) наполняет базу демонстрационными данными:

**Ингредиенты:**

| Ингредиент | Единица измерения |
|------------|-------------------|
| Картофель | гр |
| Помидор | шт |
| Огурец | шт |
| Лапша | гр |
| Макароны | гр |
| Мука | гр |
| Яйцо Куринное | шт |
| Рис | гр |
| Гречка | гр |

**Рецепты:**

| Рецепт | Ингредиенты |
|--------|-------------|
| **Яишница** | 3 яйца |
| **Жаренный рис** | 2 яйца + 500 гр риса |
| **Салат из огурцов и помидоров** | 2 помидора + 2 огурца |

> Если БД уже не пуста, демо-данные **не добавляются повторно**, чтобы не создавать дубликаты. Чтобы сбросить данные - удалите том `postgres_data` (`docker compose down -v`) или очистите таблицы вручную.

## 📦 Сборка проекта

Собрать исполняемый jar (без запуска тестов):

```bash
./gradlew build -x test
```

Готовый артефакт: `build/libs/app.jar` (имя задано в `build.gradle` → `bootJar { archiveFileName = 'app.jar' }`).

Запуск собранного jar:

```bash
java -jar build/libs/app.jar
```

## 🧪 Запуск тестов

Тесты настроены на JUnit Platform (см. `build.gradle` → `tasks.named('test') { useJUnitPlatform() }`).

Запустить все тесты:

```bash
./gradlew test
```

Отчёт о тестах: `build/reports/tests/test/index.html`.

Запустить только конкретный тест-класс:

```bash
./gradlew test --tests "org.example.recipe.service.RecipeSearchServiceTest"
```
